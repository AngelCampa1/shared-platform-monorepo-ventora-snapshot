# Metrics

Every number on this page is read from [`docs/metrics.json`](../docs/metrics.json), which
`scripts/repo-metrics.mjs` regenerates from the working tree. `pnpm run metrics:check` recomputes
all of it and fails the build if this file (or `README.md`, or `portfolio/TESTING.md`, or
`portfolio/ARCHITECTURE-PACKAGES.md`) has drifted. Nothing below is typed in by hand except the
prose between the numbers.

This document is exempt from this portfolio's usual 120 to 450 line band, the same way
[`GALLERY.md`](GALLERY.md) is: a metrics page's length tracks how many numbers exist, not how much
there is to say about them.

## Coverage

branches, and statements. All 6 Python packages set `fail_under = 95` in their own
`pyproject.toml`. 10 of the 20 TypeScript packages, including the two largest
(`@ventora/ai-sdr-worker` and `@ventora/ai-cs-worker`), exclude nothing from that gate beyond
build and test scaffolding. The full per-package exclusion table and the reasoning behind

## Where these numbers come from

`scripts/repo-metrics.mjs` walks the file list git considers part of the project (tracked files
plus untracked-but-not-ignored files), counts lines per language, counts declared test cases by
parsing source (not by running anything), and reads coverage thresholds and exclusions straight
out of every `vitest.config.ts` and `pyproject.toml`. The counting rules are unit-tested in
`scripts/__tests__/repo-metrics.test.mjs` against adversarial inputs: parametrized cases, modifier
chains, commented-out tests, and strings that merely contain the text `test(`. See
[TESTING.md](TESTING.md#four-test-tiers) for what "declared" does and does not mean.
